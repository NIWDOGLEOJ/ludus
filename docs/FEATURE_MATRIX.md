# Feature matrix

| Area | Status | Evidence / next step |
| --- | --- | --- |
| SwiftUI native shell | Implemented | Navigation and empty-state screens are in `Sources/OvercrossApp/Views`; Home shows recently played, installed, and recently added games plus real compatibility-alert and runtime-health summaries. |
| Persistent settings | Implemented | `AppSettings` persists opt-in settings using `UserDefaults`. |
| Settings navigation | Implemented | Settings is available from the main sidebar as well as the macOS Settings scene. |
| External install directory selection | Partially implemented | A native folder picker persists the preferred location, reports available volume capacity, and Heroic install/update performs a fresh preflight. A read-only Legendary JSON metadata query can display download/disk sizes and blocks installation when known required space exceeds free capacity; if the launcher does not return reliable size metadata, Overcross says so and retains the basic measurable-capacity guard. Game details report measured per-installation usage. The real Heroic adapter uses the selected location as Legendary's `--base-path`, while Steam remains delegated to Steam. |
| Application-owned cache cleanup | Implemented | Settings reports the measured size of Overcross's own application cache and, after explicit confirmation, removes only its direct contents; game installations, prefixes, runtimes, logs, and settings are outside the deletion scope. |
| Apple Silicon detection | Implemented | Runtime diagnostics reads `uname -m`. |
| macOS/developer-tool detection | Implemented | Runtime diagnostics reads `sw_vers` and `xcode-select`. |
| Existing runtime inventory | Partially implemented | Read-only detection covers common Homebrew, CrossOver, and Wine executable locations, and a native picker can inspect and persist a user-selected executable; saved runtimes are re-inspected on refresh and remain visible as unavailable when their executable disappears. Version, file-reported architecture, sibling `wineboot`, and an explicit health probe are checked. A user-provided self-contained bundle can be copied into Overcross storage only after executable SHA-256 verification; signed-source provenance and automatic downloads remain. |
| Prefix creation | Partially implemented | Uses a detected `wineboot`, explicit `WINEPREFIX`/`WINEARCH`, refuses non-empty targets, and verifies `system.reg` plus `drive_c`; no runtime is available on the current host to execute it. |
| Prefix persistence | Implemented | Verified prefix records are stored separately from game metadata. |
| Diagnostics UI | Implemented | Findings are rendered with severity and timestamps. |
| Persistent launch logs | Partially implemented | Native and Wine launch attempts persist bounded output, exit status, timestamps, and launch kind; Diagnostics can export the bounded JSON history or clear it after confirmation. |
| Unified game data model | Implemented | Store-neutral Game model exists with separate platform classification (native macOS, Windows, or unknown); Steam visible-library/local-manifest sources and the user-selected Heroic installed-cache source normalize into it with explicit ownership-evidence provenance. Store-ID and verified installation-path merging avoids duplicate records while preserving user-selected executables, favorites, and categories. Local manifests, installed caches, and user-selected executables remain visibly distinct from account-backed sources and never claim unverified ownership or compatibility. Startup/Home reconciliation clears stale installation and executable paths without deleting library records or files. |
| Game artwork | Partially implemented | User-selected local image artwork is persisted and rendered; remote store-artwork adapters remain intentionally unimplemented until their stable source and licensing are verified. |
| Persistent library metadata | Implemented | Local imports and launch results are stored in the application support directory. |
| Manual local game import | Implemented | Native file picker records a selected executable without claiming store ownership. |
| Steam local library import | Partially implemented | User-selected `steamapps` manifests are parsed and merged by Steam app ID; an installation path is recorded only when the manifest's directory exists, and an executable can be selected inside that directory; account authentication and entitlement verification remain separate. |
| Steam launcher handoff | Partially implemented | Opens a user-installed Steam application from `/Applications` or `~/Applications` and can hand a numeric app ID to Steam's `steam://run/<AppId>` protocol; authentication, Windows-build selection, and installation remain in Steam's supported workflow. |
| Library search/filter/favorites | Implemented | Unified Library filters real stored entries by title, store, compatibility, installation state, and favorite state; it sorts alphabetically, by recent launch, or by installation status, supports custom categories, and hides entries without deleting files. |
| Validated local launch pipeline | Partially implemented | Local executable validation, process launch, bounded stdout/stderr capture, exit-result persistence, and cancellation of the process started by Overcross are implemented; store launchers and runtime-specific installation remain. |
| Per-game runtime/prefix/backend persistence | Partially implemented | A verified Windows launch attempt records the stable executable-path runtime ID, prefix ID, and backend. Process exit alone does not change compatibility status; explicit profile evidence remains the source for tested-working or partially-working classification. No verified Windows launch has been executed on this host. |
| Steam authentication | Partially implemented | A native `ASWebAuthenticationSession` delegates the Steam credential form to the browser, verifies the returned OpenID callback with Steam, and persists only the numeric SteamID; visible-library discovery still requires a separate user-provided Web API key. |
| Steam Web API library discovery | Partially implemented | Uses the documented `GetOwnedGames` request with a user-provided SteamID and Keychain-backed Web API key; privacy-restricted or empty responses remain explicit, and no account-backed request has been executed on this host. |
| Epic authentication | Partially implemented | Overcross does not collect Epic credentials; after the user selects Heroic's `installed.json`, it can reuse Heroic's existing authenticated Legendary configuration to request the visible Epic library. Reconnection remains in Heroic. |
| Epic launcher handoff | Partially implemented | Opens a user-installed Heroic application and can hand an imported Epic app name to Heroic's current launch URL protocol; Overcross does not claim the game launched successfully. |
| Epic library import | Partially implemented | A user-selected Heroic/Legendary `installed.json` cache imports existing installed paths, and `legendary list --third-party --platform Windows --json` can discover the account library through the existing Heroic session without reading credentials. |
| Store installation | Partially implemented | Epic entries can run Heroic's maintained Legendary install/update/move/uninstall commands after the user selects `installed.json`, with optional read-only JSON size lookup and free-space preflight, streamed install progress, explicit destructive confirmation, bounded output, cancellation for installs, selected-base verification for installs, destination verification for moves, failed or canceled installs reconcilable from verified `installed.json` evidence, uninstall requiring explicit confirmation, and post-operation installed-record/file verification preventing false success. Legendary prerequisite installers are disabled by default and require an explicit visible setting. Steam remains a handoff because no equivalent supported local installer contract is used. |
| Prefix lifecycle | Partially implemented | Creation, validation, persistence, backup, restore, launch-time marker revalidation, and explicitly confirmed managed-prefix removal are implemented; broader game association workflows remain. |
| Compatibility profile schema | Implemented | Profiles include store/app ID, executable, runtime, prefix, backend, dependencies, arguments, environment, issues, verification date, test environment, and result; profiles can be imported from a user-selected JSON list, and a recorded executable-relative path is checked against the selected file before launch. |
| Conservative profile selection | Partially implemented | Returns only an exact store/app-ID match with a working or partially-working result and non-empty recorded test-environment evidence; no fallback is inferred, and the selected profile's evidence, dependencies, workarounds, known issues, launch arguments, and environment-override count are visible before launch. |
| Game launch pipeline | Partially implemented | Native local launch and Wine launch with runtime, verified-prefix marker, executable, runtime, prefix, required-launcher, and profile validation are implemented; store launchers and runtime-specific test execution remain. Windows detail UI now requires all three selections. |
| Downloads/cancellation | Partially implemented | Heroic installation reports parsed percentage lines, can terminate its child process, and persists a bounded operation history. Operations interrupted by app exit are marked recovery-required on the next launch; failed/canceled operations can verify an already-recorded installation directly from Downloads or be retried through Heroic. Overcross does not claim byte-level resume because Legendary owns the transfer state. Verified runtime-bundle import appears as an indeterminate verification/copy operation because the local copy has no reliable byte-progress stream; automatic runtime downloads do not yet exist. |
| Performance overlay | Partially implemented | Opt-in page samples Overcross resident memory, host physical-memory capacity, and system uptime while open; game FPS/GPU benchmarking and an in-game overlay remain. |
| Launch at login | Partially implemented | Settings calls macOS `SMAppService` and rolls back the preference when registration fails; packaged-app runtime verification remains. |
| Native operation notifications | Partially implemented | Notifications are disabled by default; when enabled and authorized, real Heroic install/update/uninstall outcomes are posted through `UNUserNotificationCenter`, with permission denial rolled back. |
| Unsigned app-bundle packaging | Implemented source-level | `scripts/package-app.sh` wraps the SwiftPM executable in an `.app` bundle and installs `CFBundleURLTypes` for `overcross://`; package build and native launch remain toolchain-blocked, while signing and notarization are separate release gates. |
| Automated tests | Partially implemented | Library, launch validation, profile selection, prefix validation, Steam import, and bounded-log tests are defined; execution awaits a matching toolchain. |
| Source verification gate | Tested | All Swift source and test files pass the available frontend syntax parse. Models/services and `AppModel.swift` also pass semantic type-checking with isolated writable caches; SwiftUI view macro expansion, XCTest execution, app launch, and store/runtime workflows remain separately tracked below. |
| Signed app packaging | Blocked | Full Xcode is not installed on the current host. |
